# 末工步与整颗结果分离候选验证与回退

日期：2026-11-06，接续终态采样工步归属修复。独立合成硬接头，不代表真实工具测量；UIO源码与固件均未修改。

## 复现与原因

真实HMI正式下发三工步：首个拧紧工步100ms超时，失败动作为继续；第二步正常拧紧；最后套筒卸荷。模型首步NOK、后两步实际完成，整颗必须NOK。原适配层把`simulator.result`直接用于所有PDO工步结果，而该字段在最后一步完成时已是整颗累计结果，于是最后卸荷步也误报NOK。

原实板记录209为`nok / ok / nok`，整颗NOK；对照“失败停止”的记录210，仅首步实际执行，后两步为not_executed。该问题不是HMI把未执行步骤补成失败，也不是UIO改变了模型反馈。

## 已试验但未闭环的候选

场景9的RUNNING→DONE完成采样仍带原工步号时，`step_result`取当前工步的`step_nok_reason`，只代表本步结果。下一拍清工步号后，继续发布`simulator.result`作为整颗累计结果。前序NOK不被清除，保护故障仍失败，STOP／RESET不延迟；没有修改接头反馈、目标、窗口或超时条件。

`tests/test_terminal_sample.c`新增首步超时继续至成功卸荷的真实适配入口回归：活动末步结果为成功，随后空闲结果仍NOK。该断言在修复前适配代码失败；修复后legacy及INT64两模式通过。全套29项C运行、4组实际映射及SDO／刷写边界回归通过，启用ASan／UBSan与断言。

候选构建为`build/hil-20261106-step-result-hard-int64`，场景9／hard／int64、Rx12B／Tx44B。刷录先备份2MiB、保留SII与扇区空洞、全片回读后恢复CPU；实际复测记录及失败证据保存在文档仓`03-计划与商务/真实HMI三板续测_20261106/`。源码／宿主验证不代替刷写后的整链关闭。

## 实板结果与回退

候选已实际刷写并完成全片回读，但记录211仍为`nok / ok / nok`，整颗NOK，故不能关闭。UIO `uio_hmi_cycle_events_feed`在工步变化边沿取**新边界帧**的step_result作为结束步结果；`ethercat_xmc_job_poll`在同一归零边界又把同字段作为整颗结果。活动末步发布正确结果一拍不足以改变上述两处取值。

若将归零边界直接改成末步成功，现行UIO只看此字段就会将整颗判OK，掩盖前序NOK，因此没有采用。需要UIO维护方和4800明确分离末步结果与累计结果：例如UIO对已执行步骤累计NOK，再用末步事实独立生成工步事件；具体接口／实现必须配套核实，不能由4800单方面改出假OK。

候选源码与红／绿宿主测试保留在文档仓忽略的`phase3/candidate-*`及本工程独立build/evidence目录。工作源码与板载均恢复`build/hil-20261106-terminal-hard-int64`对应版本，新增候选断言未并入当前通过基线。该失败继续子项保持未闭环。模型源码归属初判已更正为跨层结果语义／实现问题，不把宿主测试通过冒称整链修复。
