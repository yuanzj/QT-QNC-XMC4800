## 一、Flash返回失败处理

QEC_NvmCommit在实际编程或擦除返回false时锁存qn_fault，保留待保存状态和介质现场，清除写忙后持续发布故障4。后续START被拒绝，自动轮询和再次显式提交均不会继续触碰Flash。普通工艺RESET及重新下载工艺不能清除此故障。

不自动擦除或修复日志。故障锁存在当前运行会话内保持；设备重启执行日志校验后按介质内容恢复，未知非空或损坏的完整前缀仍阻止运行。初始化不写介质，也不把未保存的内存统计当作已持久化成功。没有新增远程清错或绕过保护接口。

新增tests/test_c21_storage_runtime.c通过实际NVM提交和实际SDO／PDO／运行许可路径验证：

- 已有日志的追加编程失败。
- 换区时擦除、复制快照、最终提交区头的返回失败。
- 无写入与部分写入后返回失败两种情况。
- 空白介质首次擦除、首次快照及首次区头编程失败。
- 标定提交失败后内存参数回滚到原值。
- 状态4发布、START拦截、普通RESET／下载不能清错、解除注入后仍不自动重试。
- 已提交活动区不被失败换区破坏；模拟重启从旧有效日志恢复，初始化不写介质。

Flash失败注入只在宿主内存介质边界返回错误，未操作实体Flash。原有257个追加写入截断点、769个换区截断点及CRC损坏恢复用例继续通过。

## 二、运行时间与主循环解耦

Simulation_Tick在原模型执行调用之外累计执行毫秒，不修改模型反馈或控制。仅统计进入本拍前仍处于RUNNING的时间区间；START之前的空闲时间、完成后的结果窗口、STOP／故障后的制动尾段不进入计时。模型补跑过程中提前完成时，以模型已有finished_ms排除其后的完成窗口。沿用原模型超过1000毫秒时基缺失的故障规则，不伪造缺失时段的执行时间。

累计计数不会随工艺RESET或重新下载清零。主循环在原中断保护范围内读取累计快照，NVM依据快照增量更新运行秒数，与轮询时是否看到RUNNING无关；维护忙碌状态只控制是否允许落盘。待处理控制命令仍优先，因其跳过一次存储轮询不会丢失累计时间。

本工程内部NVM初始化改为接收当前累计计数作为基准，轮询接收累计计数和维护忙碌标志；所有产品与宿主调用点同步修改。没有改变Flash页布局和对外对象宽度。秒数饱和到UINT32_MAX，累计计数的无符号回绕可正确求增量；不足一秒的余数仍只保存在RAM，重启仅恢复日志中的整秒值。

新增本机核对结果：

| 场景 | 结果 |
|---|---|
| 主循环每1／3／7／22／31毫秒轮询 | 各执行1100次1毫秒短循环，均累计1100毫秒 |
| 只在每颗完全结束后轮询 | 同样累计1100毫秒，修复此前记录0的问题 |
| 启动前空闲37毫秒 | 启动时累计为0，运行23毫秒后累计23，完成后累计100；未计入空闲 |
| 整段2秒运行期间不轮询 | 完成后一次轮询正确累计2000毫秒 |
| ISR补跑时短步已提前完成 | 只计实际1毫秒，不计随后完成窗口 |
| STOP／RESET／失联 | 活动区间只累计一次，制动尾段不累加；维护忙碌期间不写Flash |
| 时钟及累计计数回绕 | 正确求运行增量，不发生巨大误计 |
| 原模型时基故障、计数饱和、日志重新加载 | 通过；不把缺失时基改签正常运行，不重复累计历史时间 |
