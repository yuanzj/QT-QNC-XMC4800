# 独立合成接头与功能参考控制器 v0.3（2026-10-31）

本版按用户授权建立行业工况参考输入，供客户对照实现真实 FPGA。默认改为场景9、硬接头；场景0～8原样保留为历史协议向量。这里的“实板”指代码运行在真实 XMC4800、经过真实 EtherCAT/UIO/HMI 链路，接头和反馈仍由软件合成，没有真实电机或工具。不能用这些数据签认工具精度、夹紧力、安全等级或客户 FPGA 已完成。

## 依据及取值来源

客户 `工步示意图 v3.drawio.svg` 的八张图用于确认认帽、下旋两种、拧紧四种及卸荷的阶段与保护语义；图中输入框是示意参数，不是采样曲线。行业依据为 Atlas Copco 的 [Tightening Steps](https://picontent.atlascopco.com/cont/external/short/html/ToolsTalk-2-2-21/en-US/2216355815524358933771.html) 和 [Pocket Guide to Tightening Technique](https://www.atlascopco.com/content/dam/atlas-copco/industrial-technique/general/documents/pocketguides/9833864801_L.pdf)：硬/软接头有不同的扭矩上升率，速度、惯性及停机过程会影响过冲。上述资料用于选取阶段和检验方向，不为下表具体数值提供标定背书。

所有数值由本工程明确选定，不是客户实测，也不宣称符合某个 ISO 试验等级。没有随机噪声、测量漂移或温升模型；确定性便于定位协议和逻辑错误。缺少标定时，不凭空填充“真实采样”。

| 独立夹具参数 | 取值 | 含义与边界 |
|---|---:|---|
| 初始座面位置 | 360° | 自由旋入到座面，仅是统一试件起点 |
| 自由旋入阻力 | 0.2 Nm | 低于正常角度计数的1 Nm门槛 |
| 硬接头座面后刚度 | 1 Nm/° | 0.2→11 Nm约10.8°，用于硬接头参考 |
| 软接头座面后刚度 | 0.01 Nm/° | 同区间约1080°，用于软接头参考 |
| 合成驱动容量 | 30 Nm | 达到容量停转；不把反馈静默截成目标值 |
| 停机减速度 | 2000 rpm/s | 固定独立夹具常量；不按目标反推制动距离 |
| 卡滞位置 | 5° | 到位停转并出现容量负载，专用于卡滞保护负例 |
| 空转 | 无座面刚度 | 始终只有自由阻力，不能自动生成达标扭矩 |

这是一阶运动学、分段线性负载参考，不含电流环、柔性轴、粘滑、螺纹摩擦离散性、真实残余预紧力、松脱力矩、弹性回弹或真实STO。反转仅对同一合成接头位置减小，不是独立的拧松算法。停转卸载按固定1 Nm/ms衰减，用于区分峰值与最终值；不得用该衰减估计实际夹紧力。

## 数据流与独立性

`反馈模型 ModelPlant_Tick(速度指令, 加速时间, 驱动使能)` → 位置/速度/负载 → 量化成PDO原始值 → 参考控制器比较目标、窗口、保护 → 制动/继续/结束。

`feedback_model.c` 不接收工艺目标、判定窗口或预期OK/NOK。相同试件、相同运动指令下修改目标，不会直接改变同一时刻的负载曲线；目标可以通过正常控制决策改变何时停机。数据导出工具执行同一反馈/控制代码，没有把目标复制成曲线。模型不是客户真实FPGA算法。

每次启动显式换装一个相同的新合成试件，工步之间保留接头位置。每1ms积分速度和位置；加速时间0表示理想阶跃，非0时按指令与设定加速时间爬升。目标达到后先制动到零，再执行后延时，最后生成完成结果。停止/故障不把仍在转动的速度直接清零。运行时超过1000ms未推进的时基跳变会失败，不补造一次正常完成。

反馈缩放沿用原模型约定：编码器8388608、传动比30、量程30 Nm；扭矩1原始单位=0.03 Nm，角度位置增量按上述规格换算。它们是合成规格，不是当前真实工具身份。正常扭矩上升到角度计数门槛后，逻辑角度才开始计数；卸荷在负载下降到门槛后开始计数。图中“角度阈值”按需求解释为扭矩门槛，不是角度数值。

## 本版实际支持范围

| 原生工步 | 行为 | 明确未支持 |
|---|---|---|
| 3 拧紧61B | 扭矩、角度、OR、AND；速度、加速、窗口、活动保护、峰值/最终值、后延时、失败继续/停止 | 原生帧没有启动扭矩；自动调节、无复位组合及其他越限动作不接受 |
| 2 下旋36B | 角度模式、速度/加速、角度目标、扭矩保护、角度计数门槛、超时、后延时 | 扭矩模式需要安全角度，但现有原生帧没有该字段，明确拒绝 |
| 4 WAIT13B | 时间等待、后延时、失败动作校验 | 没有真实输入接点等待 |
| 5 卸荷26B | 同一合成接头反转卸载、阈值后角度计数、扭矩上限、超时 | 不等于拧松；没有真实套筒/弹性/松脱模型 |
| 1 认帽、6 OUTPUT | 未实现，拒绝 | 不补造认帽成败、物理DO或接点输入 |
| HMI拧松 | 未实现，客户未提供曲线 | 不自行补造拧松曲线 |

原生1/2/3/4/5/6与HMI五类工步编号不同，不能直接套用。每个未支持参数组合在解码时拒绝，不能因已接收数据就显示生产能力已实现。端点缩放和合理范围也会校验；最多16步，速度0～500rpm范围内只接受非零，角度受32位编码器范围约束。UIO现有工艺编译和能力声明由UIO负责，本版没有改UIO字段或固件。

客户图中扭矩策略只启用安全角度，角度策略只启用安全扭矩，AND启用两者，OR没有这两项保护线；所有模式仍校验最大窗口。本版不会把扭矩模式下未活动的“安全扭矩”当成需要触发的保护。安全保护和窗口上限同拍生成故障，不延迟20ms掩盖链路缺陷。

本模型测试码：`0x7002`原始范围、`0x7004`联锁、`0x7005`安全扭矩、`0x7006`安全角度、`0x7007`最大扭矩、`0x7008`最大角度、`0x7009`策略、`0x700A`时基跳变、`0x700B`反馈无效。它们不是客户正式故障码。窗口下限不合格和超时有模型内部原因，但当前原生反馈不含独立完整原因字段，不能据此声称HMI显示了精确生产原因。

## 参考数据与复现

```shell
python3 tools/generate_reference_data.py --cc clang --output evidence/reference-data
python3 tools/test_model_profiles.py --cc clang --output evidence/host-tests
python3 tools/build.py --gcc "<ARM-GCC>/bin/arm-none-eabi-gcc" --output build/hard --scenario 9 --joint hard
# 另三个夹具用 --joint soft / free-run / jam；输出目录每次使用新目录。
```

生成18组数据，每组含原生输入 `input.bin`、1ms合成反馈 `trace.csv` 和 `provenance.json`。来源记录含源码/输入/曲线SHA256、场景、夹具、预先声明的期望结果及实际终态。`export-*`是本机执行工具，不属于可移植数据集，不随客户数据交付。

| 夹具/用例 | 预期 | 检查目的 |
|---|---|---|
| 硬接头正常30rpm | OK | 非目标回填；制动后峰值12.42 Nm而非11 Nm目标 |
| 硬接头快速300rpm | NOK | 过冲触发上限，不能为通过而降低反馈 |
| 硬接头加速 | OK | 同速度、增加加速时间实际改变进程 |
| 硬接头角度/OR/AND | OK | 分别由角度、先到目标、两目标完成控制 |
| 安全扭矩/安全角度 | NOK | 适用策略下实测保护触发 |
| 窗口下限不合格 | NOK | 达到目标仍可因判定窗口不合格 |
| 停止 | NOK | 确认停止后仍有制动尾段 |
| 失败继续/失败停止 | NOK | 前者继续第二步但整颗仍NOK；后者无第二步 |
| 后延时 | OK | 包含最后一步的额外50ms延时 |
| 角度下旋/拧紧后卸荷 | OK | 角度计数与反向反馈 |
| 软接头正常100rpm | OK | 同一负载机制、不同刚度，角度显著增大 |
| 空转 | NOK | 目标不可达，超时后制动 |
| 卡滞 | NOK | 真实模型位置停止并达到负载上限 |

宿主检查包含4种独立夹具、12次历史C向量运行、2种实际PDO映射及3项刷写边界检查；使用ASan/UBSan并强制执行断言。ARM GCC的原生解码静态栈1056B，未替代完整中断栈水位/实时周期资格测试。

Mac实板复测通过UIO诊断入口发起，不是HMI点击启动；STOP由明确标识的测试控制命令发往真实UIO。被动转发和原始采样留证，不修改反馈。普通HMI业务首颗仍受工具身份缺失阻塞，不能用诊断记录签认通过。当前UIO同拍故障原因丢失也继续单列，不以整颗NOK正确代替故障归因正确。

## 客户替换顺序

先核对原生参数与实际能力，再接入真实传感与执行状态，最后用客户实测曲线标定并逐项验证策略、停机与故障原因。保留本数据集作为固定输入回归；真实实现需要另留实际工具序列号、标定日期、固件、接头材料/规格、采样条件和重复测量离散性。UIO工具身份不可用模拟假身份填充。

Windows/DAVE的旧记录保持原文、原摘要，仅证明原版本；本版新增代码取得Mac ARM GCC及宿主/实板链路验证，尚未重做Windows/DAVE整轮调试。暂停CPU会影响EtherCAT，调试必须使用对应本次固件ELF。
