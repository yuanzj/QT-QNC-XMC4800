# 客户真实实现对照指南 v1（2026-10-31）

本工程用于客户将现有逻辑 FPGA 模拟逐项替换为真实实现。交付的是完整源码和可追溯历史，不只是当前板上的 HEX。

## 先说明“默认模拟场景”

`FPGA_SIM_SCENARIO=0` 是正常模拟流程，仍包含参数接收、最多16工步、启停、模型判定与反馈。测试结束“恢复场景0”只表示不再强制注入异常，没有删除模拟层，也没有刷回 `customer-original-20261018` 客户原工程。

0～8的源码均保留，按编译宏选择。默认HEX相同说明新增异常分支未影响正常编译结果，不代表本轮没有源码更新。

| 场景 | 用途 | 客户对照点 |
|---|---|---|
| 0 | 正常确定性模拟 | 参数、状态机、工步推进、正常结果和原始反馈 |
| 1 | 扭矩NOK | 不合格反馈及后续失败动作；不是精确生产故障归因 |
| 2 | 角度NOK | 同上，覆盖角度窗口 |
| 3 | 超时 | 超时结束及结果传播 |
| 4 | 故障与结束同拍 | 故障码在结束边沿不得丢失，模型测试码0x7001 |
| 5 | 原始位置边界 | 同一步回绕、正负值、跨步归零 |
| 6 | 故障提前20ms | 与场景4作时序对照；不要为规避同拍缺陷修改正常流程 |
| 7 | 错误36B TxPDO | 映射/长度负例；正常配置是40B，不能用于正常业务联调 |
| 8 | 原始INT16/INT32极值 | 字节序、符号、单位和曲线断点；不代表可实现的工具轨迹 |

## 按这几个文件对照

| 文件 | 当前职责 | 真实实现时对照 |
|---|---|---|
| `Simulation/native_pset.c/.h` | 当前原生专家PSET的解码和必要范围校验 | 核对字段、单位、枚举和拒绝条件；模型未使用的字段不等于生产可忽略 |
| `FpgaSim/fpga_program.c/.h` | 纯C多工步逻辑、斜坡输入、启停及模型判定 | 对照执行状态、工步推进和完成/失败边沿；实际运动、采样和判定由客户真实实现替换 |
| `Simulation/ethercat_adapter.c/.h` | SDO缓冲接入，消费控制命令，回填实际对象字典 | 对照真实实现接入点，避免旧回显/模拟逻辑覆盖真实反馈 |
| `SSC/Src/QiaoTian_XMC_Servo.c`、`...Objects.h` | 对象字典、SDO/PDO映射与拷贝 | 与UIO当前适配逐字节核对，不将原工程44B RxPDO直接混入本轮12B适配 |
| `Simulation/test_mapping.h` | 场景7的映射负例开关 | 默认13条/40B；场景7为12条/36B |
| `tests/`、`tools/`、`docs/` | 独立预期、构建/保全刷写、已执行记录 | 改真实实现后，用相同输入核对正常/NOK/停止/联锁/边界，记录新的构建和结果 |

当前入口为 `Simulation_Tick → FpgaProgram_Tick`。`Simulation_Receive`仅通知收到新参数；命令1启动、2停止、3复位。停止/联锁优先于同拍成功；复位后旧任务不可直接重跑；不合法新参数不能启动旧任务。具体行为及已验证范围见原模型说明，不将宿主断言改签成实物安全验证。

反馈中 `pset_echo`高字节为PSET号、低字节为活动工步；`step_echo=0`表示没有活动工步。`0x220D`的0/1最近完成结果与UIO/HMI可靠事件枚举不同。当前步间保留20ms完成反馈供现有UIO收口，客户应核对目标接口时序，不把模拟延时当成FPGA硬件固有要求。

原生工步1/2/3/4/5/6分别为认帽/下旋/拧紧/WAIT/卸荷/OUTPUT，**不能直接当成HMI五类工步枚举**。SDO索引、字节长度及现有映射差异见[原模型说明](逻辑FPGA模型与实板资格验证_v0.2_20261030.md)和README。

## 哪些需要客户完成

当前运动波形为统一约1秒的确定性模型，并未实现真实速度/加速度环、真实扭矩法/角度法/组合策略、斜率、标定K/B、物理SPI、扳机电气、实际DO或实体STO。失败动作仅模型已列明的继续/停止，不含生产失败跳转。

客户需将实际工具原始量、真实运行状态和准确失败原因接入反馈，再逐项替换模型；`FpgaProgram_Convert`中的固定模型规格不能直接当成实物标定值。不能通过把模拟函数改名为FPGA驱动来视为真实实现完成；物理接口和控制算法以客户实际规格为准。

## 构建和复验

默认导入工程为场景0。命令行构建可显式选择场景，编译器路径换成本机安装位置：

```shell
python3 tools/build.py --gcc "<ARM-GCC>/bin/arm-none-eabi-gcc" --output build/reference-normal --scenario 0
python3 tools/build.py --gcc "<ARM-GCC>/bin/arm-none-eabi-gcc" --output build/reference-map-negative --scenario 7
python3 tools/build.py --gcc "<ARM-GCC>/bin/arm-none-eabi-gcc" --output build/reference-integer --scenario 8
python3 tools/test_model_profiles.py --cc clang --output evidence/host-reference
```

Windows可将 `python3` 换为 `python -X utf8`，编译器使用对应 `.exe`。宿主检查需要支持ASan/UBSan的C编译器；它不连接板卡。固件输出和证据目录必须使用新目录。

本轮Mac使用ARM GCC14.2.1；Windows/DAVE历史编译、调试记录原样保留，新增代码尚未重新取得Windows/DAVE整轮验证。客户用DAVE重编译后，调试应加载该次匹配ELF，不拿旧ELF配新源码。Windows步骤见[DAVE说明](DAVE客户导入与断点调试说明_20261030.md)。

刷写仍需指定XMC探针，备份完整2MiB、保留SII、完整读回后恢复CPU。本轮打包不重新刷板，不更改UIO/HMI及在用数据。
