# 原始位置边界向量与恢复验证

2026-10-30。以客户原工程和既有独立模型为基础，为串联方案 TC-HIL-MAP-04 增加编译场景5。客户原版标签和通信适配保持不变，本次只改 `FpgaSim/fpga_program.c/.h`、构建选项并增加宿主断言。

## 输入及边界

默认 `FPGA_SIM_SCENARIO=0`；场景5代码只在显式选中时编入。场景5是C类原始位置测试输入，经真实4800 PDO、UIO和HMI传输，不是FPGA/SPI、电机运动或紧固质量算法。

测试使用原生专家拧紧工步、角度复位开启、1000ms确定性时序、小角度/扭矩合法参数。速度反馈固定为0，不把位置跳变解释成物理速度。普通参数校验、联锁、停止和完成逻辑继续生效。

| 输入 | 原始位置与时刻 | 实板重复及结果 |
|---|---|---|
| 单拧紧，正方向 | +2147483000；300ms起变为−2147483000，STEP仍为1 | 3次，每次30006一次、零丢帧断点一个 |
| 单拧紧，反方向 | 上述符号相反 | 3次，结果相同 |
| 拧紧后等待 | STEP1为+2147483000，STEP2为0 | 3次，不误报同一步回绕 |
| 正拧紧后反拧紧 | STEP1正边界、STEP2负边界 | 3次，不误报同一步回绕 |
| 反拧紧后正拧紧 | STEP1负边界、STEP2正边界 | 3次，不误报同一步回绕 |

整数差由核对程序使用宽整数计算，模型本身没有执行有符号溢出。参考编码器8388608、减速比30时，边界位置约±3071.999072°，存储Float32约±3071.999023°。多步场景只验证STEP边界判别，不覆盖任意角度累计参数组合。

## 编译及宿主验证

```shell
python -X utf8 tools/build.py --gcc "<ARM-GCC>/bin/arm-none-eabi-gcc.exe" --scenario 5 --output build/position-test
zig cc -std=c99 -Wall -Wextra -Werror -UNDEBUG -DFPGA_SIM_SCENARIO=5 tests/test_position_vector.c FpgaSim/fpga_program.c -o position-test.exe
./position-test.exe
```

独立断言检查299/300ms、两个方向、20ms步间完成保持、跨步归零、停止与联锁。原场景0～4、适配层及3项刷写边界测试继续通过。

场景5ARM GCC制品HEX SHA256为 `201bfa04c8c72cafbeda3567e81743f0305b0e7284a50f287fcaf9667ef83c0e`。源码快照、编译器、输入摘要和制品摘要随本机构建清单保存。

## 数据核对与限制

15次向量实板运行对应HMI记录104～118，21171个高清点与独立原始帧换算/API一致，15000个缩略点均来自原始数据。340个相关TCP包保持逐字节一致。6次同一步回绕各一个断点、各一次30006，丢帧数均0；9次跨步测试没有回绕误报。实时推送亦保留6个断点，各循环只有一条结果推送。

3类跨步输入首轮另出现31010：此测试刻意从非零绝对边界开始，工步事件角度按终点减起点为0，与曲线绝对位置不同，触发现有结果/曲线一致性检查。保留该观察，不能签真实质量算法通过，也未据此认定新的UIO产品缺陷。

## DAVE正常构建及恢复

本轮另在新工作区使用DAVE 4.5.0的CDT无界面构建入口导入并构建Debug。无界面启动应使用去掉 `-showlocation` 的临时启动配置，导入路径使用 `file:///` URI；失败尝试日志保留。最终构建成功，原有两项未使用变量警告仍在。此次不是新版GUI或断点复验；原GUI和实板断点记录见[DAVE说明](DAVE客户导入与断点调试说明_20261030.md)。

正常HEX与增加场景5前相同；ELF因源码/行号变化更新，调试须使用此ELF与匹配源码。IDE自动改动的工程元数据另留证后恢复，未纳入本次代码差异。

恢复正常模型时，完整读回及SII保留成功，但首次CPU恢复失败：执行方在刷写命令尚未结束时提前启动了恢复命令，造成探针竞争。原 `cpu_running=false` 和失败日志保留。待全部探针进程退出后，单独串行恢复CPU、请求从站恢复，确认OP/WKC3/3；随后3次正常运行通过，记录119～121无缺口、最大角度约11.988°。板上已退出场景5。

刷写、调试、恢复必须串行，等待前一进程退出并检查结果后再执行下一条；CPU或OP未确认时，测试前置检查拒绝提交任务。正常恢复完整Flash摘要为 `f4f14a3b97ff9d59b6a72d8b362e73fd9bf2e4ab1bed0e8e243c5d35d56f71db`，与原正常Flash相同。刷写/暂停期间WKC累计错误由190增至220，15次向量运行和3次正常运行期间均没有新增，RPMsg丢弃为0。

UIO源码和固件未改。全部运行由诊断入口发起，不代签HMI发起的G1、真实停止保护、物理扳机或长期运行验收。
