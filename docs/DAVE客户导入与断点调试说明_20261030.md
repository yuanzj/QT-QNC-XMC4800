## 1. 导入与编译

1. 安装 DAVE 4.5.0，使用其自带ARM-GCC-49；推荐工程放在英文路径。准备Python 3.12和SEGGER J-Link，本轮实测J-Link V9.60。
2. 获取本独立仓库，启动DAVE并选择一个新的工作区，避免与客户原工程重名。
3. `File > Import > General > Existing Projects into Workspace`，选择包含`.project`和`.cproject`的仓库根目录。建议不勾选复制到工作区，直接使用Git目录。
4. 工程名仍为 `DOCH_ECAT_XMC48_Servo_Probe_20261018`。在 `DAVE IDE` 透视图中，选择 `Project > Build Configurations > Set Active > Debug`，再按 `Ctrl+B`。
5. 产物为 `Debug/DOCH_ECAT_XMC48_Servo_Probe_20261018.elf` 和同名`.hex`。Release配置的产物在Release目录，默认没有源码调试信息，断点验证使用Debug。

源码、SDK和SSC均在仓库内，无需额外C12依赖包。Debug/Release目录可由DAVE重建。不要用旧电脑的对象文件代替当前源码编译。

本次原生导入使用DAVE自带CDT导入入口，GUI中打开并编译；上述通用导入向导是客户操作入口。可选命令行等效入口如下，先关闭使用同一工作区的DAVE：

```powershell
& '<DAVE目录>/eclipse/eclipsec.exe' -nosplash `
  -vm '<DAVE目录>/eclipse/jre/bin/java.exe' `
  -application org.eclipse.cdt.managedbuilder.core.headlessbuild `
  -data '<新工作区绝对路径>' `
  -import 'file:/C:/work/QT-QNC-XMC4800' `
  -build 'DOCH_ECAT_XMC48_Servo_Probe_20261018/Debug'
```

`-import`使用file URI；路径中的空格用`%20`。直接写`C:/...`会被旧Eclipse当作名为C的文件系统协议，本次曾因此导入失败，改为file URI后成功。

## 2. 封存并下载DAVE生成的固件

在仓库根目录运行。所有尖括号内容换成本机值，输出目录使用新名称：

```powershell
python -X utf8 tools/package_dave.py --configuration Debug `
  --gcc '<DAVE目录>/eclipse/ARM-GCC-49/bin/arm-none-eabi-gcc.exe' `
  --output build/dave-debug01

python -X utf8 tools/flash.py --build build/dave-debug01 `
  --jlink '<J-Link目录>/JLink.exe' --serial <XMC探针序列号> `
  --evidence evidence/dave-flash01 --confirm
```

封存入口核对源码/对象/ELF时间关系，重新从ELF导出HEX并与IDE产物比较。刷写入口完整备份、保留应用扇区原有空洞、跳过SII，完整回读一致后才恢复CPU。日志失败时先查看失败阶段。

调试配置关闭IDE自动下载，以便使用上述保留SII和扇区空洞的刷写流程。板上镜像、封存ELF和IDE所用Debug ELF须一致；源码重新编译后应重新封存和刷写。

## 3. 生成本机调试配置

```powershell
python -X utf8 tools/configure_dave_debug.py --dave '<DAVE目录>' `
  --jlink-server '<J-Link目录>/JLinkGDBServerCL.exe' `
  --serial <XMC探针序列号>
```

生成根目录 `XMC4800-WAIT-Attach.local.launch`，该文件被Git忽略，客户本机路径及探针号不会进入共享提交。已有文件不覆盖；需要新配置时可增加 `--output 另一个名称.local.launch`。

在DAVE刷新工程，打开 `Debug Configurations`，选择 `GDB SEGGER J-Link Debugging > XMC4800-WAIT-Attach.local`，核对：

- Main：本工程、Debug目录ELF、Debug构建配置。
- Debugger：XMC4800-2048、SWD、1000kHz、指定XMC探针序列号；GDB使用DAVE自带版本。
- Startup：Load image关闭，Load symbols开启；本例使用硬件断点，Flash breakpoints关闭。
- 初始化命令为 `monitor halt` 和 `hbreak FpgaSim_Tick`。

点击Debug，接受Debug透视图切换。连接后可能先停在复位入口并显示 `No source available for 0x8000200`；按F8运行到模拟层断点，不要据此判断为源码缺失。

断点命中后应显示 `Thread #1 ... (Suspended : Breakpoint)`、`FpgaSim_Tick() at fpga_sim.c:40`。按F6，本轮空闲分支停在第50行；可展开调用栈、查看Variables。在Debugger Console中输入：

```text
print *sim
info args
info breakpoints
```

本轮读取到 `state=FPGA_SIM_IDLE`、`started_ms=0`、`duration_ms=0`、`result=0`，参数 `now_ms=0`、`permitted=0`。这是空闲分支调试证据，不是运行中业务结果。`info breakpoints`确认类型为hw breakpoint。

## 4. 结束调试并恢复通信

在Debugger Console执行 `delete 1` 移除本例初始化断点，按F8恢复运行，再按Ctrl+F2终止会话。确认J-Link GDB Server与GDB均已退出，再运行：

```powershell
python -X utf8 tools/recover_link.py --jlink '<J-Link目录>/JLink.exe' `
  --serial <XMC探针序列号> --url 'http://<UIO地址>:8080' `
  --evidence evidence/dave-recover01

python -X utf8 tools/test_wait.py --url 'http://<UIO地址>:8080' `
  --evidence evidence/dave-business01 --repeat 3
```

实际观察到IDE终止后CPU停在复位入口；仅请求UIO恢复不能让暂停CPU继续运行。恢复工具先定向连接XMC并执行g，确认CPU运行，再请求UIO恢复并核验OP/WKC；不刷写固件。断点暂停会打断EtherCAT周期，不应把该窗口内的掉线计入正常运行稳定性结果。
