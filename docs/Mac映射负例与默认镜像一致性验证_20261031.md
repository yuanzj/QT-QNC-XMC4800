# Mac 映射负例与默认镜像一致性验证（2026-10-31）

本轮仅扩展测试模型，不修改客户原始标签，也不修改 UIO 固件。Windows 2026-10-30 的 DAVE 构建、断点与历史测试记录保持原件；本记录不把 Mac 命令行验证改签为 Windows/DAVE 新版本验证。

## 新增场景 7

`FPGA_SIM_SCENARIO=7` 明确制造 36 B TxPDO 映射，供串联方案 TC-HIL-MAP-05 的长度不匹配负例使用。`Simulation/test_mapping.h` 控制 0x1A00 条目数及拷贝长度；`APPL_InputMapping` 在该场景不写第 36～39 字节，避免向 36 B 缓冲越界。

默认场景仍为 0、13 条映射、40 B TxPDO，不改变任何默认反馈时序，也不以延迟故障等手段遮住 UIO 问题。场景 5、6 的原始位置向量及同拍/提前故障测试含义保持已有文档说明。

## 新增场景 8：原始整数边界

`FPGA_SIM_SCENARIO=8` 仅在逻辑模型的拧紧分支注入已知原始量，每 100 ms 换一组。扭矩包含 INT16 最小/最大、-1、0、1、1000、123、2000；位置与速度包含 INT32 最小/最大、-1、0、1、±8388608、4194304。这是 C 类固定输入，不代表真实工具轨迹，也不据这些输入评判物理算法。

`tests/test_raw_integer_vector.c` 对 1000 个 tick 独立核对字面向量，并核对停止/互锁优先级；ASan/UBSan 检查通过。场景 8 HEX SHA-256：`78d74df36d70b2d1b7db3eea020da19b773196fdc90e744e67b189ff560a68a9`。

4800 实刷两轮并保留三条 HMI 曲线（102、103、107），三条均逐组包含八组不同的整数输入，独立按工具配置换算一致；同一步位置跳变产生 30006 和断线。HTTP 低频轮询最初漏看短平台，原脚本失败保留，以实际持久化曲线核对补证，没有延长模型平台来迁就轮询。

两轮均在 finally 中恢复正常应用，完整 2 MiB 与原正常备份逐字节一致，SII 未变。加入场景 8 后默认场景重新构建，HEX 仍与上表默认 SHA 完全一致。当前板上恢复为默认场景 0；匹配的 Mac ELF 为本轮 `normal-after-8` 构建，不把 ELF 调试段相同与 HEX 可执行字节相同混为一谈。

## 结论边界

本轮覆盖真实 EtherCAT/SDO/PDO 与逻辑 FPGA 模型。正常、NOK、位置边界及故障输入属于 B/C 类替代，不能代签真实 FPGA 算法、物理 SPI、实际工具精度、实体 STO 或 HMI 正常启动首颗闭环。
